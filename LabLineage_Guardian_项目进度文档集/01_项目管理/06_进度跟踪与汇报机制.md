# 进度跟踪与汇报机制

## 1. 节奏

| 频率 | 活动 | 输出 |
|---|---|---|
| 每日异步 | 更新任务状态、阻塞和下一步 | 看板变更 |
| 每周 | 45 分钟项目例会 | 周报、关键路径、风险更新 |
| 双周 | Demo / 技术评审 | 可运行增量、评审记录 |
| 每阶段 | Gate 评审 | 通过、条件通过、整改或回退 |
| 发布前 | Go/No-Go | 发布检查清单 |

## 2. 进度衡量

不以“代码行数”衡量。采用：

- 已验收任务人日 / 当前阶段总任务人日；
- 核心用户旅程通过率；
- 关键路径剩余天数；
- P0/P1 风险与缺陷数量；
- 平台正式链路覆盖率；
- 测试、Agent eval、谱系准确率与业务指标。

## 3. 偏差阈值

| 偏差 | 动作 |
|---|---|
| 单任务超估算 50% | 拆分、重新估算、记录根因 |
| 关键路径延迟 3 个工作日 | 项目负责人提出纠偏 |
| 里程碑预测延迟 1 周 | 启动范围或资源变更评审 |
| P0/P1 安全问题出现 | 暂停相关发布和试点 |
| 外部平台权限不确定超过最晚日期 | 启用降级计划并向组委会确认 |

## 4. 周报最少内容

- 本周完成的可验收成果；
- 未完成任务及原因；
- 下周关键目标；
- 新风险、假设变化和决策；
- 需要他人或外部支持的事项；
- 指标和质量趋势；
- Demo 是否仍可运行。
