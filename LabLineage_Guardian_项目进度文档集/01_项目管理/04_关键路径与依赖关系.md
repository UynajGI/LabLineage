# 关键路径与依赖关系

## 1. 主关键路径

```mermaid
flowchart LR
  A[比赛资源确认] --> B[平台最小Spike]
  B --> C[PRD与数据契约]
  C --> D[Collector与Manifest]
  D --> E[幂等导入与数据库]
  E --> F[谱系与审计核心]
  F --> G[ADK工具与工作流]
  G --> H[Runtime部署]
  H --> I[Registry与Gateway治理]
  I --> J[Workspace闭环]
  J --> K[Beta安全质量门禁]
  K --> L[三类试点]
  L --> M[RC与比赛交付]
```

## 2. 次关键路径

### 路径 A：无 Git 追踪

`哈希规范 → 本地索引 → 快照 → diff → 变更 UI → 试点验证`

### 路径 B：GitHub 对齐

`GitHub 权限 → commit/tree → 文件匹配 → dirty diff → 冲突 Finding → Agent 解释`

### 路径 C：安全治理

`数据分类 → 脱敏 → 身份/IAM → Gateway 策略 → 红队 → 试点授权`

### 路径 D：量化影响

`用户访谈 → 指标定义 → 黄金数据 → 人工基线 → 试点前后对比 → 比赛叙事`

## 3. 关键外部依赖

| 依赖 | 可能影响 | 缓解 |
|---|---|---|
| Gemini Enterprise 权限开通时间 | Runtime/Registry/Gateway 无法正式验证 | 先本地 ADK 开发；设置平台 Spike 最晚决策点；不把模拟结果当正式集成 |
| Google Cloud 额度和有效期 | 成本与环境持续性 | 预算告警、staging 自动关停、保留本地 Demo |
| Agent Platform 区域可用性 | 资源无法共区 | P1 阶段冻结区域；Registry/Gateway/Runtime 同区域核验 |
| Workspace 组织策略 | OAuth、Drive、Gmail 权限受限 | 使用比赛测试账号和专用共享盘；只创建草稿 |
| GitHub 私有仓库权限 | 无法演示真实仓库 | GitHub App 最小权限；准备公开/测试私有仓库 |
| 试点课题组授权 | 无法采集真实指标 | 尽早招募；准备匿名合成样例与严格区分的模拟指标 |
| 组服务器网络限制 | 云端无法实时查询 | 离线签名 Bundle 为正式支持模式，不视作降级缺陷 |

## 4. 依赖管理规则

- 任务依赖使用任务 ID，不使用口头描述；
- 外部依赖必须有最晚确认日期；
- 关键依赖延迟超过一周时，项目负责人必须提出范围、顺序或资源调整；
- 不允许通过伪造接口或硬编码结果“消除”依赖；
- 任何替代实现必须在 Demo 和文档中明确其状态。
