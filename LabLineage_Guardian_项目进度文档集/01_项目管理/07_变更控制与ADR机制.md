# 变更控制与 ADR 机制

## 1. 需要变更单的事项

- 核心用户、主要场景或非目标变化；
- 新增数据源、自动执行或删除能力；
- 原始数据上云边界变化；
- 数据库主模型或 Manifest 不兼容变更；
- Agent 工具权限扩大；
- 项目周期、里程碑或比赛承诺变化；
- 引入 AlphaEvolve、图数据库、向量数据库等重大技术。

## 3. ADR

架构决策记录应回答：

- 背景和约束；
- 决策；
- 被考虑的替代方案；
- 正负后果；
- 回退条件；
- 相关任务、接口和文档。

首批 ADR 建议：

1. ADR-001：云端为控制面，原始科研数据默认不出域；
2. ADR-002：MVP 使用 PostgreSQL 节点/边表而非图数据库；
3. ADR-003：完全离线以签名 Bundle 为一等模式；
4. ADR-004：确定性事实与 Gemini 推断分离；
5. ADR-005：不自动删除结果；
6. ADR-006：AlphaEvolve 不进入关键路径。
