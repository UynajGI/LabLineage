## 1. 文档集用途

这不是 48 小时黑客松冲刺表，而是一套普通软件项目可持续执行的进度文档。它用于：

- 将设计方案拆成可分配、可估算、可验收的工作包；
- 明确 Gemini Enterprise Agent Platform 四个核心组件在项目中的真实任务；
- 跟踪组内服务器、GitHub、无 Git 快照、科研谱系、审计、Workspace 和安全等不同类别；
- 以里程碑 Gate 控制范围和质量，而不是到最后才拼接 Demo；
- 为比赛提交保留一条可复现的工程证据链。

## 5. 状态定义

| 状态 | 含义 |
|---|---|
| `未开始` | 尚未投入有效工作 |
| `准备中` | 依赖、设计或环境正在准备 |
| `进行中` | 已有负责人和有效产出 |
| `阻塞` | 存在必须先解决的外部或内部依赖 |
| `待评审` | 产物已提交，等待验收 |
| `已完成` | 达到验收标准并合入基线 |
| `已取消` | 经变更流程确认不再执行 |

## 6. 关键原则

- AlphaEvolve 不是本项目关键路径；除非后续发现明确可量化、需要进化算法的子问题，否则不引入。
- 原始科研数据默认留在组内服务器；云端接收策略裁剪后的 manifest、证据、哈希、摘要和报告。
- GitHub 是代码证据源之一，不是假定所有科研目录都有 Git。
- 确定性工具负责事实，Gemini 负责语义解释、跨来源归纳和交接协作。
- Agent Runtime、Registry、Gateway 必须各自承担部署、目录治理和策略控制职责，不能只出现在架构图里。
- 所有高风险写操作均需人工确认；MVP 不提供自动删除科研文件。
