# 比赛条件摘录与项目映射

## 1. 比赛提供条件

- Gemini Enterprise 及 Agent Development Kit、Agent Runtime、Agent Registry、Agent Gateway 的使用条件；
- Google Cloud 额度，具体额度和有效期以组委会通知为准；
- Gemini API / Google AI Studio 模型调用能力；
- 官方文档与快速上手示例。

## 2. 本项目如何使用

| 比赛条件 | LabLineage Guardian 的真实使用 |
|---|---|
| Gemini Enterprise | 作为科研交接智能体的统一使用入口和治理环境 |
| ADK | 编排谱系查询、审计、人工确认与报告工作流 |
| Agent Runtime | 部署和管理 Guardian Agent，提供日志、会话和扩展能力 |
| Agent Registry | 登记 Agent、GitHub/Edge/Workspace MCP 和后端 Endpoint |
| Agent Gateway | 控制 Agent 对工具和服务的访问，实施身份、allow/deny 和审计 |
| Google Cloud 额度 | 承担 Runtime、API、数据库、存储和可观测性环境成本 |
| Gemini API / AI Studio | 开发阶段模型实验、结构提取、证据解释和报告生成 |
| Google Workspace | Drive 报告、Sheets 台账和 Gmail 整改草稿 |

## 3. 不使用 AlphaEvolve 的理由

比赛示例不是强制技术清单。本项目的核心困难是跨来源证据建立、语义解释、权限治理与离线数据边界，而不是有明确数学 evaluator 的组合优化问题。强行引入 AlphaEvolve 会增加复杂度并削弱 Google Workspace 与 Agent 平台的主线。若后续出现可自动评分的关系解析或策略优化子问题，可作为非关键研究分支评估。
