# 比赛资源开通与验收

## 1. 已知比赛条件

根据比赛页面，参赛团队将获得或可使用：

- Gemini Enterprise 及其智能体组件权限；
- 可在 Google Cloud Console 兑换的 Google Cloud 额度；
- Gemini API，可通过 Gemini API 或 Google AI Studio 调用模型；
- 具体额度、有效期和最终权限以组委会通知为准。

本计划不预设额度数值、截止日期、可用区域或所有功能均已开通。

## 3. 资源开通顺序

1. 接受比赛邀请并确认组织/项目归属；
2. 创建专用 Cloud 项目，避免和个人实验混用；
3. 兑换额度并设置预算告警；
4. 确认 Agent Platform 支持区域；
5. 配置管理员、开发者、部署和 Agent 身份；
6. 完成 Gemini API 最小调用；
7. 完成 ADK 本地 Agent；
8. 部署 Runtime 测试 Agent；
9. 注册测试 Agent/MCP/Endpoint；
10. 创建 Gateway 并验证允许/拒绝；
11. 建立 Workspace 测试共享盘、Sheet 和 Gmail 草稿权限。

## 4. 最小验收场景

用户向 Runtime 中的测试 Agent 提问，Agent 通过 Gateway 调用一个已在 Registry 登记的只读测试工具，返回结果，并在日志中看到：

- 用户或调用主体；
- Agent 身份和版本；
- Gateway 策略；
- 工具名称与结果；
- 请求延迟与错误；
- 禁止工具调用被拒绝。

## 5. 成本保护

- dev/staging 默认低并发；
- 大批量解析在边缘或确定性后端完成，不用 LLM 扫描每个文件；
- 将复杂推理与简单提取分配给不同模型；
- 每次试验记录模型、token、延迟和成本；
- 定期清理闲置 Runtime、Gateway、数据库和对象存储；
- 额度到期前导出所有配置和演示包。
