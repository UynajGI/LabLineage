# 用户故事验收标准

## US-01 图像来源追踪

**Given** 项目包含图像、日志、脚本、GitHub 仓库和参数候选  
**When** 用户询问图像来源  
**Then** 系统必须：

- 返回至少一个候选生成链；
- 标记 exact/strong/inferred/hypothesis；
- 引用 evidence ID；
- 显示缺失条件；
- 不把多个冲突候选强行合并；
- 支持人工确认。

## US-02 GitHub 冲突

- 具体分支必须解析为 commit SHA；
- 服务器文件精确匹配时显示一致；
- 不一致时给出最近候选和受控 diff 摘要；
- 不能把服务器 mtime 当 Git 历史；
- 生成 P1/P2 Finding 的规则有测试。

## US-03 无 Git 更新记录

- 第一次扫描形成不可变基线；
- 第二次扫描可识别新增、修改和删除；
- 移动/重命名只能以候选表示，除非人工确认；
- 大文件指纹强度可见；
- 快照中断不会破坏上一版。

## US-04 模组梳理

- 自动生成模组候选；
- 展示上下游边和未知边；
- 用户可重命名、合并、拆分；
- 人工修改有历史；
- Agent 解释不能隐藏低置信关系。

## US-05 结果筛选

- 结果同时有可复现等级和业务状态；
- duplicate、failed、stale、orphan 有独立证据；
- exploratory 不等同垃圾；
- 所有删除建议只能进入人工清理清单。

## US-06 离线交接

- Bundle 不含策略禁止字段；
- Bundle 有签名和校验和；
- 损坏或篡改能够被发现；
- 导入幂等；
- 报告明确哪些内容因离线和脱敏不可见。

## US-07 Workspace 闭环

- Sheet 更新幂等；
- Drive 报告有审计 ID 和版本；
- Gmail 只创建草稿；
- 写操作前用户确认；
- Workspace 失败不会改变本地审计事实。
