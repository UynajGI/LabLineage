# 从这里开始

LabLineage Guardian 用证据回答三个问题：

1. 一个科研结果由哪些数据、代码、参数、环境和运行生成？
2. 现有证据足以支持“可复现”到什么程度？
3. 把项目交给下一位研究者时，还缺少什么？

第一次使用不需要理解数据库、OIDC、GCS 或 Agent。先选择与你最接近的角色。

## 选择入口

| 我是谁 | 先完成什么 | 从哪里开始 |
|---|---|---|
| 研究者或接收项目的人 | 浏览一个已有项目，理解谱系、风险和交接预览 | [10 分钟体验](quickstart.md) |
| 需要采集科研目录的人 | 建立项目、生成 Manifest、导入并检查结果 | [接入第一个项目](first-project.md) |
| 审计员 | 判断候选关系，处理发现并留下审核证据 | [用户指南](user-guide.md)第 3–5 节 |
| 实验室管理员 | 配置身份、数据库、对象存储和平台集成 | [管理员指南](administrator-guide.md) |
| 运维或发布负责人 | 部署、监控、备份、恢复和回滚 | [运维手册](operations-runbook.md) |
| 开发者 | 启动工作区、运行测试并提交代码 | [README](../README.md) |

不确定时，从 10 分钟体验开始。它只使用演示数据，不会扫描你的目录，也不需要模型密钥。
没有真实项目但想验证采集能力时，使用
[`examples/reference-study`](../examples/reference-study/README.md)；实现约束见
[Run lineage v1 技术设计](run-lineage-v1.md)。

## 一张图理解工作流

```text
科研目录或平台
      ↓ 采集
Snapshot / Manifest / Bundle
      ↓ 导入并校验证据
Node + Edge + Evidence
      ↓ 确定性审计
Finding + R0–R4
      ↓ 人工确认
版本化交接预览
```

- **Node** 是数据、代码、参数、环境、运行、图表或结论。
- **Edge** 表示“使用了”“生成了”等关系。
- **Evidence** 是哈希、签名记录、平台事件或人工审核记录。
- **Finding** 是需要处理的风险，不等于删除科研结果。
- **R0–R4** 表示证据支持的可复现级别；R4 只能由成功且输出哈希匹配的受控重跑产生。

更多定义见[核心术语表](glossary.md)。

## 第一次使用的安全边界

- 先用演示数据或科研目录的非敏感副本。
- 不要把 `.env.local`、`.lablineage/`、私钥、原始科研数据或导出报告提交到 Git。
- Collector 默认只导出路径 Token、哈希和结构化元数据，不导出绝对路径或原始文件内容。
- “候选”关系是推断，必须经过审计员确认后才能成为人工验证证据。
- 本地交接只创建不可变预览；Workspace 导出必须先预览并明确确认，Gmail 只创建草稿。

## 什么算第一次成功

完成以下四项即可，不需要先配置生产环境：

- 页面顶部显示 `LIVE API / 真实后端数据`。
- 能在 Lineage Explorer 中解释 `fig3.png` 的上游证据。
- 能运行一次审计并区分发现、建议和证据。
- 能创建本地交接预览，并看到 export ID、文件数量和成功状态；没有邮件被发送。

如果其中一步失败，先查看[用户指南的常见问题](user-guide.md#8-常见问题)，再进入管理员或运维文档。
